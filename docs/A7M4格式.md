# A7M4 导入格式（camera-look v2 JSON）

> 与 A7R V（`R5NATIVE.BIN`，卡根目录、整套 12 槽）**完全不同族**。A7M4 只认
> `PRIVATE/M4ROOT/GENERAL/LUT/*.json`，一个文件一个滤镜。

## 硬约束（相机侧）

| 项目 | 限制 |
| --- | --- |
| 目录 | `PRIVATE/M4ROOT/GENERAL/LUT/`（相对卡根；不递归扫描子目录） |
| 目录条目 | ≤ 256 项（非 JSON 文件与子目录也计数；第 257 项直接扫描失败） |
| 单文件 | 非空且 ≤ **131,072 字节（128 KiB）** |
| 文件名 | 含 `.json` ≤ 63 UTF-8 字节，不以点开头，扩展名大小写不敏感 |
| `name` 字段 | ≤ 63 UTF-8 字节（与文件名是两条独立限制） |
| 机内槽位 | 16 个，可替换/删除 |

## 结构（官方校验器 `vendor/m4/look_v2.py` 为准）

```
format: "camera-look"   version: 2   model: "ILCE-7M4"
engine_abi: 131072 (0x20000)   mode: "photo"   draft: false
id: 小写规范 UUID（非零）   revision: 正整数
name ≤63B / author ≤63B / description ≤1024B
defaults: contrast, highlights, shadows, fade, saturation,
          sharpness(0..9), sharpness_range(1..5), clarity —— 八项整数
parameters.photo: coefficients.values[3][8] int16
                  matrices.values[3][16][6] int16
                  gamma.records[7][572] uint8
parameters.live : 同形状,gamma.records[1][572](context 6)
parameters.grid : {"mode":"disabled"} 或
                  {"mode":"custom","encoding":"a7m4-grid405-native-s7-v1",
                   "photo":[3][5][9][9],"live":[3][5][9][9]}  值域 −64..63
required_capabilities: 排序后的精确集合
  基础三能力 + 启用网格时追加 "native-grid405-separate-v1"
payload_sha256: sha256(b"CAMLOOK2\0" + 规范化 JSON(
  只用 format,version,model,engine_abi,required_capabilities,id,revision,
  draft,mode,name,parameters,defaults;键排序,紧凑分隔符)) 的 64 位小写 hex
```

## 本工程的实现

- `src/r5lut/m4json.py`
  - `load_seed()` 读合法种子（官方解析 + 全字段校验）
  - `build()` 从种子派生：替换 `photo/live` 网格、改名、换 UUID、`draft=false`
  - `seal()` 重算 `payload_sha256`；`encode()/write()` 紧凑编码并强制 ≤128 KiB
- `vendor/m4/`：官方 `look_v2.py` + `native_codec.py` + `photo_profiles.json`（逐字副本）

自检：

```bat
set PYTHONPATH=D:\ai逆向\r5lut\src
py -3 -c "from r5lut import m4json; s=m4json.load_seed(r'种子.json'); v=m4json.build(s,name='X',author='me',description='d'); print(m4json.write(r'out\x.json', v))"
```

写出的文件必须能被相机导入前通过官方 `look_v2.parse` —— 本工程在写出后立即回读校验。

## 从 `.cube` 到 M4 JSON 还差什么

`.cube` 是 sRGB 显示域颜色映射，M4 JSON 是**相机原生参数 + 405 残差网格**。转换必须
在 M4 相机模型上拟合（与 A7R V 的 R5 模型不是同一套）：

1. 冻结 M4 模型：`M4-training-assets/models/`（bridge + grid_response + forward_model）
2. 大色卡输入与目标：`charts/sony_input.npz`（原生前段输出 `front`）、
   `charts/fuji_targets.npz`（12 款目标）、`charts/design_pairs.npz`（分割/设计值）
3. 以某个合法 JSON 作**原生种子**（`Lut-v1.0.2.zip` 内 15 个），只拟合 405 网格
   （photo/live 同步），原生参数不动——否则还要 Sony Edit 参考文件与 `srsettings0000.tbl`
4. 拟合完成后用 `m4json.build()` 写盘，`look_v2.parse` 复核，再上机确认

> 目前缺少的：M4 拟合侧代码（本项目尚未移植）+ 若要动原生参数还需 Sony Edit 二进制
> 与 `srsettings0000.tbl`（官方要求使用者自行取得）。

```bat
set PYTHONPATH=D:\ai逆向\r5lut\src

  --lut-dir "C:\Users\杨\Desktop\lut" ^
  --assets  "D:\ai逆向\a7r5-ref\a7m4\assets\M4-training-assets" ^

```

产物：
- `<out>/PRIVATE/M4ROOT/GENERAL/LUT/*.json` —— 全部成品（拷卡用）
- `<out>/report.json` / `report.csv` —— 每个 look 的 `test_mae8` / `test_de00` / 耗时
- 单张约 24 秒（RTX 4060，GPU 拟合）；`--steps 2500` 可再降 3–8% 误差，单张约 60 秒

指标判读：ΔE00 **越小越好**（0–1 肉眼难分，1–2 细看可辨，2–5 观感相近，>10 基本两种风格）。

黑白一类（去饱和）网格会顶到 ±64，需改用原生参数承载：以 `ACROS.json` 为原生种子，
`chart_native` 重算前段后走官方 `fit_grid`，实测 ΔE00 从 9.9–11.6 降到 2.1–5.4。

## 语义边界（与 FORMAT.md 对齐后的结论）

| 项 | 结论 | 依据 |
| --- | --- | --- |
| `photo` / `live` 网格是否必须不同 | 可以相同 | 官方 `Lut-v1.0.2` 的 15 个参考 look **全部** photo/live 网格逐值相同 |
| `defaults` 是否参与调色 | 否 | 官方 15 个 look 的 `defaults` 完全一致（0,0,0,0,0,4,3,1） |
| `provenance` | 可选，本工程写入 | 记录 cube 的 SHA-256、模型合同、拟合统计、边界声明；合同明确它不构成精度承诺 |
| 格式通过 ≠ 颜色一致 | 需分开评估 | FORMAT.md L39/L41 |

## 原生参数联合搜索:实测结论（负结果,已记录）

按官方 `native_family`（116 方向:12 Gamma bump / 96 矩阵项 / 8 CC1 系数）+ 一阶整数贪心实现，
在黑白 look 上跑了 3 轮（每轮：量雅可比 → 选整数步 → `native_family.safe` 物化 → 重算 `chart_native` → 网格重拟合 → 表路径复核）：

| 轮 | 原生 L1 | ΔE00 | mae8 |
| --- | --- | --- | --- |
| 0 | 0 | **6.49** | 16.92 |
| 1 | 10 | 6.75 | 17.90 |
| 2 | 20 | 8.45 | 24.09 |

结论：**这条路径在黑白上不改善**（网格热启动、冷启动都一样）。原因是残差的量与方向对不上——
黑白需要的是大幅去饱和（网格已全部顶在 ±64），而 116 方向里 Gamma bump 保持端点、
矩阵每步只给 24 个 int16 单位、CC1 系数每步 8 个单位，覆盖不到这个量级。

模块保留为实验工具（`src/r5lut/m4native.py`），默认不参与出包；黑白目前最好的方案仍是
「ACROS 原生种子 + 表路径优化的 405 网格」，实测 2.99 / 3.19 / 6.49 / 7.82。
要真正解决黑白，需要的是更接近单色的原生种子（例如官方风格的 BW 参数集），而不是在这 116 个方向上微调。
