# 工程质量

本项目按「可交付软件」的标准维护：静态检查、严格类型、单元测试、可复现构建。
所有门禁在本地与 CI（`.github/workflows/quality.yml`）中一致。

## 门禁

| 门禁 | 命令 | 当前状态 |
| --- | --- | --- |
| 静态检查（pycodestyle/pyflakes/bugbear/simplify/pathlib…） | `py -3 -m ruff check src tests` | 0 问题 |
| 格式（black 风格） | `py -3 -m ruff format --check src tests` | 全部已格式化 |
| 严格类型（`strict = true`） | `py -3 -m mypy` | 0 问题（6 个源文件） |
| 单元测试 | `py -3 -m pytest -q` | 11 通过 / 1 跳过（慢测试需 `R5_SLOW=1`） |

一条命令跑完：

```bat
检查.bat
```

## 设计约束（代码层面的硬规则）

1. **不 exec、不 eval、不拼 shell**：引擎一律 `subprocess.run([...])` 传参数列表。
2. **编码显式**：所有文本读写成 UTF-8；兼容 Windows 杂乱编码时走
   `utf-8 → gbk → latin-1` 回退链，禁止依赖进程 locale。
3. **失败要可解释**：对外只抛 `R5Error(message, detail)`，`detail` 保留引擎原始输出。
4. **产物可验**：BIN 编译后与 finish 记录比对（字节数 + SHA-256），不一致直接拒绝交付。
5. **身份固定**：模型/色卡/基线哈希不符即拒绝训练，不做「尽力而为」。
6. **测试只碰公开缝**：单元测试走 CLI 与 `core` 公共函数，不 mock 引擎内部实现。
7. **打包两形态**：源码运行（`py -3 -m r5lut`）与 frozen exe（引擎外置目录），
   两条路径共用同一份 `core`，差异集中在 `engine_root()` / `_python_cmd()`。

## 目录职责

| 路径 | 职责 |
| --- | --- |
| `src/r5lut/core.py` | 管线编排：prepare → fit → finish → compile → pc → grid → diagnostics |
| `src/r5lut/cli.py` | 命令行入口与退出码（0 成功 / 1 用法 / 2 运行失败） |
| `src/r5lut/gui.py` | Tk 单窗口界面（参数、预览、进度） |
| `src/r5lut/preview.py` | 自包含颜色预览：CUBE 解析、三线性采样、PNG 编解码 |
| `engine/` | vendored 官方训练引擎（AGPL-3.0，不改其公开接口） |

## 已知边界

- 引擎内部 `numpy/scipy/torch` 动静不计入 mypy（vendored 代码按原样保留，只在
  `engine/` 里做最小兼容补丁，见 `engine/VENDORED-NOTES.md`）。
- 慢测试（真训练）默认跳过：`set R5_SLOW=1` 才执行。
